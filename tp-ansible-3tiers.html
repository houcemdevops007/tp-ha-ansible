Déployer une architecture web avec Ansible
HAProxy · Apache · Tomcat

Vous allez automatiser de A à Z le déploiement d'un load balancer HAProxy qui répartit le trafic entre deux pools de serveurs indépendants : un site statique sous Apache et une application Java sous Tomcat.

6 VM1 contrôleur + 5 cibles
4 rôlescommon, apache, tomcat, haproxy
≈ 6 hdurée indicative
Rocky Linux 9sur Proxmox
Objectifs Architecture Environnement Applications Étapes Vérifications Exercices Livrables

1Objectifs pédagogiques

À la fin de ce TP, vous serez capable de :

📋 Inventorier

Organiser un inventaire Ansible en groupes (lb, web, app) avec des variables par groupe.

🧩 Structurer

Découper un projet en rôles réutilisables (tasks, handlers, templates, files, defaults).

🧪 Générer

Produire des fichiers de configuration dynamiques avec Jinja2 à partir de l'inventaire.

⚖️ Répartir

Configurer HAProxy avec plusieurs backends, des ACL de routage et des health checks.

🔒 Sécuriser

Gérer firewalld, SELinux et les secrets avec ansible-vault.

✅ Valider

Tester l'idempotence, la répartition de charge et la tolérance aux pannes.

4Applications à déployer

Les applications sont fournies dans les rôles : aucun téléchargement externe ni compilation n'est nécessaire.

Apache Site statique

  • index.html : accueil affichant le hostname et l'IP du serveur
  • about.html : présentation du TP
  • health.html : page de health check
  • style.css : couleur différente par serveur
HTML/CSS pur, généré par des templates Jinja2.

Tomcat Application Java /app

  • index.jsp : hostname, heure, ID de session, compteur de visites
  • health.jsp : renvoie OK
  • WEB-INF/web.xml : descripteur de l'application
Pages JSP compilées par Tomcat, sans Maven ni base de données.

5Déroulé du TP, étape par étape

1

Préparer le nœud de contrôle

⏱ 20 min
  • Générer une clé SSH et la copier sur les 5 VM cibles (ssh-copy-id)
  • Créer le répertoire du projet tp-3tiers/ et l'initialiser avec Git
  • Écrire un ansible.cfg local : inventaire par défaut, remote_user, become
ssh-keygen -t ed25519
for h in lb01 web01 web02 app01 app02; do ssh-copy-id $h; done
2

Construire l'inventaire

⏱ 20 min
  • Déclarer les groupes lb, web et app dans inventory/hosts.ini
  • Créer group_vars/ : ports, versions, nom des backends
  • Tester la connectivité :
ansible all -m ping
ansible-inventory --graph
3

Créer la structure des rôles

⏱ 15 min
ansible-galaxy init roles/common
ansible-galaxy init roles/apache
ansible-galaxy init roles/tomcat
ansible-galaxy init roles/haproxy

Repérer le rôle de chaque dossier : tasks, handlers, templates, files, defaults, vars.

4

Rôle common

⏱ 30 min
  • Installer les paquets de base (vim, curl, chrony…)
  • Démarrer et activer firewalld et chronyd
  • Vérifier que SELinux est en mode enforcing (on ne le désactive pas !)
5

Rôle apache : site statique

⏱ 45 min
  • Installer httpd, démarrer et activer le service
  • Déployer les pages avec le module template (variables ansible_hostname, ansible_default_ipv4.address)
  • Copier style.css avec le module copy
  • Ouvrir le service http dans firewalld
  • Déclarer un handler restart httpd
Test intermédiaire : curl http://web01/ doit afficher le nom web01.
6

Rôle tomcat : application Java

⏱ 60 min
  • Installer Java (OpenJDK 17)
  • Créer l'utilisateur système tomcat, télécharger et décompresser Tomcat dans /opt/tomcat
  • Créer le service systemd à partir d'un template
  • Déployer l'application dans webapps/app/ (JSP + WEB-INF/web.xml)
  • Ouvrir le port 8080/tcp et déclarer un handler restart tomcat
Test intermédiaire : curl http://app01:8080/app/ doit afficher app01.
7

Rôle haproxy : le load balancer

⏱ 60 min
  • Installer haproxy
  • Écrire le template haproxy.cfg.j2 :
    • frontend sur le port 80 avec l'ACL path_beg /app
    • backend web_apache et backend app_tomcat générés par une boucle sur groups['web'] et groups['app']
    • option httpchk sur chaque backend
    • page de stats sur le port 8404, avec un mot de passe stocké dans un vault
  • Valider la configuration avant de l'appliquer : validate: haproxy -c -f %s
  • Activer le booléen SELinux haproxy_connect_any et ouvrir les ports 80 et 8404
{% for host in groups['web'] %}
    server {{ host }} {{ hostvars[host].ansible_host }}:80 check
{% endfor %}
8

Playbook principal et déploiement

⏱ 30 min
  • Écrire site.yml : un play par groupe (common sur tous, puis web, app et lb en dernier)
  • Faire un test à blanc, puis le déploiement réel :
ansible-playbook site.yml --check --diff
ansible-playbook site.yml --ask-vault-pass
Idempotence : relancez le playbook. Le récapitulatif doit afficher changed=0 pour tous les hôtes.

6Vérifications et tests

  • Répartition sur Apache : les réponses alternent entre web01 et web02
  • Répartition sur Tomcat : les réponses alternent entre app01 et app02
  • Page de stats http://lb01:8404/stats : les 4 serveurs sont UP
  • Tolérance aux pannes : après l'arrêt de httpd sur web01, tout le trafic passe sur web02
  • Même test sur Tomcat avec app01
for i in {1..6}; do curl -s http://lb01/ | grep -o 'web0[12]'; done
for i in {1..6}; do curl -s http://lb01/app/ | grep -o 'app0[12]'; done

ansible web01 -b -m service -a "name=httpd state=stopped"

Dépannage rapide

SymptômePiste
Backend DOWN dans les statsLe chemin du health check existe-t-il ? Testez-le avec curl depuis lb01
503 Service UnavailableSELinux : getsebool haproxy_connect_any, ausearch -m avc
Connexion refuséefirewalld : firewall-cmd --list-all sur le serveur cible
/app renvoie 404Dossier webapps/app, droits de l'utilisateur tomcat, logs/catalina.out
HAProxy ne redémarre pashaproxy -c -f /etc/haproxy/haproxy.cfg

7Exercices complémentaires

Facile

Scale-out

Ajoutez un serveur app03 uniquement dans l'inventaire, relancez le playbook et vérifiez qu'il apparaît dans HAProxy.
Moyen

Déploiement ciblé

Modifiez le site, puis redéployez seulement le rôle Apache avec un tag (--tags apache) et --limit.
Moyen

Sticky session

Le compteur de visites repart à zéro ? Activez l'affinité de session par cookie sur le backend Tomcat.
Avancé

HTTPS

Générez un certificat auto-signé avec Ansible et activez la terminaison TLS sur HAProxy (redirection 80 → 443).
